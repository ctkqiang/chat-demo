# Live 语音（Live Voice Mode）

输入框右侧的 **实时语音** 按钮开启语音通话：应用持续聆听，回答边生成边朗读，说话即可打断。

## 通话式设计：不往聊天里打字

Live 语音是**电话式通话**，与聊天界面完全独立：

- 通话期间**不写入聊天界面**：你说话不会变成聊天消息，AI 回复也不显示为打字；
  全屏界面里的字幕只是通话的实时字幕。
- 通话维持自己的私有对话上下文（开始时从当前会话的可见对话播种，AI 记得之前聊过什么），
  每轮问答追加到私有历史里，形成连续通话。
- **退出通话时**，整通电话（全部轮次）一次性保存为聊天记录，落到通话开始时的会话
  （会话不可用时新建）；被打断的轮次记为「已停止」，出错的轮次不保存。

## 架构说明：级联链路，不是全双工

DeepSeek 公开 API **没有实时语音（speech-to-speech）接口**，因此语音通话是三条现有接口的级联（cascade）：

```
麦克风 → 浏览器 VAD 判定一句话结束
       → POST /v1/tools/asr 整句转写
       → 追加到通话私有上下文 → LLM 流式回复（streamMessage）
       → 浏览器端按句切分 → POST /v1/tools/tts 逐段朗读（DeepSeek 音色）
```

与 ChatGPT/Claude Live 的全双工语音相比，级联链路有两个固有限制：

1. **转写延迟**：ASR 是整句一次性转写，一句话说完才开始识别、提交，LLM 也才开始生成；
2. **打断语义**：模型生成期间并不真正“听”你说话。检测到打断后，应用立即停止本地音频
   并取消通话内当前回复的生成，把你说的新一句话作为新一轮提问提交（与 ChatGPT Live 一致）。

因此 UI 与文档统一称为「低延迟实时语音 + 打断（barge-in）」，不宣称全双工。

### 状态机

```
idle ──开启──▶ listening ──一句说完──▶ thinking ──首段正文──▶ speaking
                 ▲                        │  ▲                   │
                 └──────回答读完──────────┘  └── 检测到说话 ──────┤
                                                               ▼
                                        interrupted ──转写提交──▶ thinking
                                             │
                                             └──没有有效语音──▶ listening
任意状态 ──退出/出错──▶ idle / error
```

## 打断（barge-in）如何工作

- 能量 VAD（RMS 滞回）在 `speaking` / `thinking` 期间检测到说话，立即执行：
  停止全部已排程的 TTS 音源并关闭播放 AudioContext（本地静音远快于 150ms 目标）、
  取消当前回复的流式生成、清空 TTS 队列与句子缓冲。
- 麦克风使用 `echoCancellation`，尽量降低扬声器回声触发误打断；阈值可在
  `src/services/liveVoice/config.ts` 调整。
- 打断后识别到有效语音则提交新问题；没有有效语音则回到聆听状态。
  无论哪种情况，被打断的回复生成已取消，退出通话时记为「已停止」保存。

## 流式朗读

- 回复正文增量经过 `SentenceChunker` 按句切分：代码块与数学公式默认不读，
  链接只读文字（可选读地址），图片不读，标题/列表/引用/表格标记被剥离；
  未闭合的 Markdown 结构（链接、行内代码、数学）会等待补齐，不会从中间截断。
- `SegmentAssembler` 把**第一句完整句子立即提交** TTS（首句延迟最影响通话感），
  之后的短句攒够长度再合并为一次请求。
- `PlaybackQueue` 在 24kHz AudioContext 上把各段 PCM 连续排程，当前段开始播放时
  预取下一段，段间只有约 50ms 的间隔。

## 环境变量与实时适配器（预留）

| 变量                      | 说明                                                         | 默认               |
| ------------------------- | ------------------------------------------------------------ | ------------------ |
| `LIVE_VOICE_REALTIME_URL` | 实时语音服务地址（构建期注入 `__LIVE_VOICE_REALTIME_URL__`） | 空（使用级联链路） |

接入真正的实时语音服务时，实现 `src/services/liveVoice/transport/LiveVoiceTransport.ts`
接口（WebSocket 全双工），并在 `RealtimeSpeechAdapter.ts` 里按地址构造。当前构建未包含
任何实时后端实现：配置了地址但未提供实现时，开启 Live 语音会明确报错，绝不把级联链路
伪装成全双工。示例见 `.env.example`。

## 浏览器支持

- 需要安全上下文（HTTPS、localhost 或 file://）与 `AudioWorklet`：
  Chrome/Edge 66+、Firefox 76+、Safari 14.1+。
- 不支持时 Live 按钮置灰，tooltip 说明原因。
- 麦克风权限被拒绝、没有输入设备、ASR/TTS/网络失败都会进入 `error` 状态并给出文案，
  退出后重新开启即可恢复；所有资源（麦克风轨道、AudioContext、worklet、订阅）在退出时释放。

## 全屏界面

开启后整个站点进入全屏 Live 界面（与 Gemini Live / ChatGPT 语音模式一致）：
中央球体在聆听时随麦克风音量起伏、朗读时呼吸、思考时外圈旋转；
球体下方实时显示本轮对话字幕（你的原话 + 助手边生成边刷新的正文）；
右下角 ×、底部「退出实时语音」按钮或 Esc 退出，回到原来的聊天页面。
退出后对话照常保存在消息列表里。

### 说话中的实时字幕

DeepSeek 的 ASR 不是流式接口（一句话说完才整段转写），因此「说话中逐字显示」的字幕
来自**浏览器本地语音识别**（SpeechRecognition）的 interim 结果，仅用于展示；
提交给模型的文本始终以 DeepSeek ASR 为准，两者可能略有差异。

- 只在 Chrome / Edge 上启用；Firefox 不支持、Safari 的 webkitSpeechRecognition 与页面
  麦克风采集存在冲突风险，这些环境自动降级为「说完才显示转写」。
- 识别音频会发送给浏览器厂商的语音服务处理；不需要时把
  `src/services/liveVoice/config.ts` 的 `ENABLE_INTERIM_CAPTIONS` 改为 `false`。
- 识别失败（权限被拒、网络不可用）时静默降级，不影响 Live 语音本身。

## 手动测试清单

1. `pnpm dev` 打开 http://localhost:8090，在设置中填入 API Key。
2. 点击输入框右侧 **实时语音**：授权麦克风后进入全屏通话界面，球体随音量起伏，显示「正在聆听…」。
3. 说一句话，停顿约 0.7 秒：状态变为「正在思考…」，字幕区出现你的提问，
   随后「正在说话…」，助手回复边生成边显示边用 DeepSeek 音色朗读——**聊天页面全程不变**。
4. 在朗读中直接说话：音频立即停止，状态显示「已打断」，你说的话会作为新一轮提问提交。
5. 回答朗读完毕后回到「正在聆听…」，像打电话一样连续对话；点击 ×、底部退出按钮或按 Esc 挂断。
6. 挂断后回到聊天页：**整通电话已保存为会话里的对话记录**（被打断的轮次显示「已停止」）。
7. 普通文字聊天、一次性语音输入、朗读按钮、历史导入导出均不受影响。
8. 回归：`pnpm type`、`pnpm lint`、`pnpm test`（单元测试覆盖状态机、VAD、句子切分、片段组装）。

## 已知取舍

- ASR 不是流式接口：一句话结束才开始转写（约 1–2 秒），这是级联链路固有的延迟，
  也是「说完整句才接话」的原因——DeepSeek 公开 API 的上限。
- 通话只在退出时落盘：中途刷新页面会丢失未结束的通话记录。
- 通话上下文从开始时的会话播种，通话期间聊天页不可见、也不会变化。
- 打断阈值按常见麦克风标定；环境噪声较大时可在 `config.ts` 提高 `onsetRms`。
